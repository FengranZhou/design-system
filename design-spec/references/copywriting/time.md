# 通用时间文案规范 (Time Copywriting)

> 文案规范层规则。接到「展示时间 / 时间戳 / 日期 / 更新时间 / 创建时间」等任务时，**动手前必读本文件**：按「格式规则」定展示形态、用源头 `formatTime` 落地、避开「反例」、直接套用「可照抄骨架」。读之前不要凭直觉自拟日期格式或硬编码时间字符串。
>
> 时间格式化有**唯一可执行实现** `design-spec/utils/format-time.ts`，任何展示通用时间的地方都 import 它，不各自重写、不硬编码日期字符串——规范改一处、处处同步。

---

## 一、何时用（触发条件）

命中以下任一，即用本规范：

- 列表 / 表格里的**时间列**（创建时间、更新时间、提交时间…）。
- 时间线 Timeline、动态流、卡片、详情页里的**时间戳**。
- 任何"把一个时间点展示给用户看"的场景。

> 反过来：**只要是展示给用户看的通用时间，就走 `formatTime`，不要手写 `2026-03-17` 这种硬编码字符串，也不要用 EP 默认的 `YYYY-MM-DD HH:mm:ss`（带秒、且不省略本年年份，均不符合本规范）。**

---

## 二、格式规则

| 场景 | 格式 | 例 |
|---|---|---|
| **本年内** | `MM-DD HH:mm`（省略年份） | `03-25 13:00` |
| **非本年** | `YYYY-MM-DD HH:mm`（完整年份） | `2024-12-21 13:00` |
| **精度** | 时间根据需求展示，若需要则**精确至分钟**即可 —— **不展示秒** | `13:00`，不是 `13:00:42` |
| **只到日期** | 该场景本就无时分语义时，**只给日期、不带时分** | 本年 `03-25`；跨年 `2024-12-21` |

要点：
- **本年内省略年份**：减少冗余（用户默认理解是今年），信息更聚焦。
- **跨年才带完整年份**：避免歧义。
- **不展示秒**：秒对绝大多数业务展示是噪音；确有需求（如日志、精确到秒的审计）才例外，那属于专门场景，不走本通用规范。
- **「根据需求展示」= 时分是可选的**：需要时点就带时分，不需要就只给日期 —— 用
  `formatTime(t, 'day')`。判据是**该字段本身有没有时点语义**：
  「提交时间 / 更新时间 / 操作时间」有（几点几分是信息）→ 默认 `'minute'`；
  「入职日期 / 截止日期 / 生日 / 单据日期」没有（只有"哪一天"）→ 用 `'day'`。
  ⚠️ **数据源只有日期时（如 `'2024-03-15'`）必须传 `'day'`** —— 否则 `formatTime`
  会补出一个并不存在的 `00:00`，且因时区偏移常显示成 `08:00`，等于凭空捏造精度。

## 三、强制做法

### 1. 一律 import 源头 `formatTime`，不重写、不硬编码 <!-- @rule id=time-use-formattime level=MUST cat=文案规范 view=impl detect=regex dtitle=时间展示格式全站统一（本年省年份、不显示秒） title=时间展示一律 import 源头 formatTime，禁各自写格式化函数/硬编码时间字符串 -->

```ts
import { formatTime } from '<path>/design-spec/utils/format-time'

formatTime('2026-03-25 13:00')          // → '03-25 13:00'（本年内，默认带时分）
formatTime('2024-12-21 13:00')          // → '2024-12-21 13:00'（非本年）
formatTime(Date.now())                  // 接受 string | number | Date

// 第二参数 = 展示精度，缺省 'minute'
formatTime('2026-03-25 13:00', 'day')   // → '03-25'（只到日期）
formatTime('2024-03-15', 'day')         // → '2024-03-15'（纯日期数据必须传 'day'）
```

- 省略年份 / 跨年判断 / 补零 / 不带秒，全在 `formatTime` 内处理好，**渲染处**只管传入原始时间。
  ⚠️ 「谁来调」这一步不要想歪：若该字段由业务组件渲染（如 `DataTable` 的 `kind:'date'` 列），
  **组件内部就是那个"渲染处"，数据层不要再调一次** —— 详见下方第 3 条。
- **绝不**在业务里各自写一遍格式化逻辑，也**绝不**把展示结果写成硬编码字符串（如模板里直接写 `timestamp="2026-03-17"`）。

### 2. 原始数据带到分钟精度

- 存储 / 传入 `formatTime` 的原始时间应包含到分钟（`YYYY-MM-DD HH:mm`），由 `formatTime` 决定展示时是否省略年份。
- 不要在数据源就把时间截成"只有日期"——那样跨年判断和"精确到分钟"都无从谈起。

### 3. 谁渲染谁格式化 —— 组件内部已格式化的，数据层不要再调一次 <!-- @rule id=time-no-double-format level=MUST cat=文案规范 view=impl detect=ast dtitle=时间不要格式化两次（会把年份错成 2001） title=组件内部已调 formatTime 的字段，数据层禁止预先 formatTime -->

**双重格式化会静默错年份**：`formatTime` 本年省略年份，输出 `08-20 23:59`；这个串再喂给
`new Date()` 会被 JS 当成无年份而解析到 **2001 年**，页面显示 `2001-08-20 23:59` ——
**不报错、不告警，只能靠眼睛发现**。
（⚠️ 更隐蔽的是：跨年数据带完整年份、二次解析结果不变，所以拿一条去年的数据测试会「一切正常」。）

**判据：看这个字段最终由谁渲染。**

| 渲染方 | 数据层该传什么 | 谁负责格式化 |
|---|---|---|
| **业务组件**（内部已调 `formatTime`） | **原始时间串** `'2026-08-20 23:59'` | 组件 |
| 自己写的模板 / 单元格 | 原始时间串 | 你自己在模板里 `{{ formatTime(t) }}` |

**已知内部会格式化的组件**（用它们时数据层不要再调 `formatTime`）：

- **`DataTable` 的 `kind: 'date'` 列** —— 传原始串；精度用列上的 `timePrecision: 'day'`，
  不要自己调 `formatTime(t, 'day')`。

> `formatTime` 自 v1.5.2 起对自己的输出**幂等**（`formatTime(formatTime(t)) === formatTime(t)`），
> 可兜住已经写错的代码。但幂等是**兜底不是许可** —— 正确写法仍是数据层传原始值。

### 4. 展示层只调用、不加工

- 在模板里 `{{ formatTime(row.updatedAt) }}` 即可，不要在外面再拼字符串、再截断。

---

## 四、反例（禁止）

- ❌ **硬编码时间字符串**（`timestamp="2026-03-17"`、`<span>03-25 13:00</span>` 写死）—— 脱离规范、跨年不会自动带年份、改规则不同步。
- ❌ **各自再写一份格式化函数** —— 规则散落，改一处漏一处；必须 import 源头 `formatTime`。
- ❌ **用 EP / 库默认格式**（`YYYY-MM-DD HH:mm:ss`）—— 带秒、本年不省略年份，违反格式规则。
- ❌ **本年内仍显示年份**（`2026-03-25 13:00`）—— 本年必须省略年份，显示 `03-25 13:00`。
- ❌ **展示到秒**（`13:00:42`）—— 通用展示不带秒。

---

## 五、可照抄骨架

```vue
<template>
  <!-- 表格时间列：用 formatter 包一层，不直接打印原始值 -->
  <el-table :data="rows">
    <el-table-column prop="name" label="名称" />
    <el-table-column
      prop="updatedAt"
      label="更新时间"
      :formatter="(_r, _c, v) => formatTime(v)"
    />
  </el-table>

  <!-- 卡片 / 列表条目里的时间戳同理，一律 formatTime 包一层 -->
  <!-- <span class="card__time">{{ formatTime(item.updatedAt) }}</span> -->
</template>

<script setup lang="ts">
import { formatTime } from '<path>/design-spec/utils/format-time'

// 原始时间带到分钟；formatTime 决定展示是否省略年份、是否跨年
const items = [
  { raw: '2026-03-17 09:30', label: '提交需求文档' },
  { raw: '2026-03-15 14:00', label: '完成设计评审' },
]
</script>
```

> 照抄要点：**原始时间带到分钟 → 展示统一 `formatTime()` 包一层**。省略年份、跨年带年份、不带秒一概不用手写——全由源头 `formatTime` 保证。
