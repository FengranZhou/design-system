# 工具栏布局模式 (Toolbar Pattern)

> 设计模式层规则。接到「做工具栏 / 页面头部操作条 / 列表页顶部一排（标题 + tab + 筛选 + 搜索 + 操作按钮）」的任务时，**动手前必读本文件**：先按「组件排序逻辑」定内部顺序、再按「左右分配三分支」定哪些靠左哪些靠右、间距与内边距走固定令牌，避免每次凭直觉把这排东西乱摆一版各页不一致。
>
> **核心思想**：工具栏不是"把标题、筛选、按钮随手排一排"，而是**一条固定顺序 + 一套左右分配规则**。顺序固定 → 全站工具栏元素相对位置一致；左右分配按"有没有标题、有没有筛选类组件"分三种分支 → 视觉重心稳定。

---

## 一、何时用（触发条件）

命中以下任一，即用本模式：

- 做**列表页 / 表格页顶部的操作条**（标题 + 筛选下拉 + 搜索 + 新建/导出按钮那一排）。
- 做**模块卡片的头部工具栏**（模块标题 + 组件级 tab + 操作按钮）。
- 任何"一排里同时有：标题 / tab / 下拉选择器 / 搜索框 / 操作按钮 中的两类及以上"的横向组织。

> 反过来：**只要这排东西里出现了标题、tab、筛选、搜索、操作按钮的组合，就按本模式的固定顺序 + 左右分配摆**，不要每个页面各摆各的。

---

## 二、组件排序逻辑（固定顺序）

工具栏内的元素**一律按此顺序从前到后排列**（无论最终落在左侧还是右侧，相对先后不变）：

```
标题 → 组件级 tab 栏 → 下拉选择器 → 搜索框 → 次按钮 → 主按钮
```

| 序 | 元素 | 说明 |
|---|---|---|
| 1 | **标题** | 页面标题 / 模块标题 / **页面级 tab 栏** / **模块级 tab 栏**（这四者都算"标题"，见下方说明） |
| 2 | **组件级 tab 栏** | 页面/模块内切换视图的 tab（**不算标题**，算右侧功能组件） |
| 3 | **下拉选择器** | 筛选 / 类型选择（`el-select`，见 select-pattern） |
| 4 | **搜索框** | 列表检索（见 search-pattern） |
| 5 | **次按钮** | 次要操作（默认态 `el-button`） |
| 6 | **主按钮** | 主操作（`el-button type="primary"`，一排只一个主操作） |

> **关键区分「标题级 tab」vs「组件级 tab」**：
> - **页面级 / 模块级 tab 栏** → 承担"我在哪个页面/模块"的导航职责 = **当标题用**，放左侧。
> - **组件级 tab 栏** → 在当前页面/模块内切换内容视图（如"全部 / 待办 / 已完成"）= **功能组件**，与下拉/搜索同列，放右侧。

---

## 三、强制做法

### 1. 左右分配：按三分支依次判定（互斥，命中即止）

| 分支 | 条件 | 左侧 | 右侧 |
|---|---|---|---|
| **①** | **有标题**（含页面级/模块级 tab 栏） | 标题 | 其余全部（组件级 tab / 下拉 / 搜索 / 次按钮 / 主按钮） |
| **②** | 无标题，但**有** 组件级 tab / 下拉 / 搜索 中任一 | 组件级 tab / 下拉 / 搜索 | 操作按钮（次按钮 / 主按钮） |
| **③** | 无标题，**也无** 组件级 tab / 下拉 / 搜索 | 操作按钮（次按钮 / 主按钮） | —（无右侧） |

- 判定顺序 ① → ② → ③，**从上往下第一个命中的分支即为最终布局**。
- 左右两侧各自内部，**元素仍按「二」的固定顺序**排列。

### 2. 布局、间距、标题字阶 —— **在源头，使用方不写**

以下**已固化在 `el-theme/patterns/toolbar.scss`**，写上约定 class 即生效，**使用方不必也不应重写**：

- **外层 `space-between` 分左右两组**（`__left` / `__right` 各自 flex）。分支 ③（只有操作按钮）时不写 `__right` 即可，左组自然靠左。
- **相邻元素水平间距** `12px`（`spacing-3`）：由 `.toolbar__left` / `.toolbar__right` 的 gap 提供，**不在元素上写 margin**（同按钮间距规范）。
- **标题字阶两档**：`.toolbar__title` 默认页面级（`title-page` 26/48），加 `--module` 降为模块级（`title-module` 18/36）。
- **工具栏内 tab** 的 header 下边距清零（使其与同排元素垂直居中）。

### 3. 留白 —— **由页面给出（源头不含任何内边距）**

`.toolbar` **不含任何内边距**，两个方向各有其归属：

**左右 —— 属于「页面内容区容器」，由容器统一给一次**

按 `foundations.md` 间距速查：**页面内容与页面左右边缘之间 = `spacing-6`（24px）**。这是**容器**的内边距，工具栏、列表、表单等所有内容共用同一次，自然左右齐平。

- ⛔ **不要写进工具栏**：容器已给内边距时会叠加成 48；工具栏以外的内容还得各自再对齐一遍。

**上下 —— 工具栏与页面上下文的间距，按标题层级取档**

按 `foundations.md` 间距速查：

| 位置 | 令牌 | 值 |
|---|---|---|
| 页面级标题与页面顶部之间 | `spacing-4` | 16px |
| 页面级标题与其下方内容之间 | `spacing-4` | 16px |
| 模块级标题与其下方内容之间（层级更轻，收一档） | `spacing-3` | 12px |

- 容器**上下已有留白**时不必再加，避免叠加。

```css
/* 容器给左右（一次，所有内容共用） */
.page-content { padding-inline: var(--iflyv-spacing-6); }

/* 页面级标题工具栏 */
.page-content > .toolbar { padding-block: var(--iflyv-spacing-4); }
/* 模块级标题工具栏：下方收一档 */
.page-content > .toolbar--module { padding-block-end: var(--iflyv-spacing-3); }
```

> 一律走令牌，禁裸值（`padding: 16px 24px` ❌）。

### 4. 每类元素仍走各自的组件 / 模式

工具栏只管"排布"，每个元素本身仍遵守既有规范：下拉→select-pattern、搜索→search-pattern、按钮→按钮章节（主操作唯一、图标走 #icon 插槽）、tab→tabs 约定类。

### 5. 过滤条件的数量与合并（列表页工具栏专用）

列表页的筛选区最容易失控——把业务字段一股脑平铺出来，看似"功能齐全"，实际**用户宁可忽视也不用**（条件太多，找一个比不找还累）。两条硬规则：

**① 过滤条件不超过两行**（平铺形态除外）。超出即**收折**：高频条件前置常显，低频条件收进「更多筛选」。纵向空间被筛选区吃掉，表格本身可视行数就少了。

**② 并列同义的条件必须合并，不能各占一席**——判据是**这些条件之间能否产生交集**：

| 情形 | 处理 |
|---|---|
| 多个字段是**并列关系**，同时填不产生交集（`反馈ID` / `关键词` / `订单号`——用户只会用其中一个找同一条记录） | 合并为**一个多字段模糊搜索**框 |
| 两字段存在**包含/联动关系**（`反馈分类` ⊃ `所属BU`；教育场景如 `学院` ⊃ `专业` ⊃ `班级`） | 合并为**多层级级联下拉** |
| 各条件互不重叠、组合后能**逐步收窄**结果 | 保持独立，这才是多条件过滤的正确形态 |

> **为什么**：多条件过滤的目的是**交叉收窄**——每多选一个条件，结果集应该更小。并列同义的条件放在一起并不产生交集，只是让用户在一堆框里犹豫该填哪个。

> **权重最高的那个互斥维度（通常是「状态」）应升为 tab**，不占筛选区位置；但**必须先确认该维度无交集**，见 `component-interaction.md` Tabs 段的前置硬规则。

## 四、反例（禁止）

- ❌ **顺序乱摆**（把搜索放主按钮后面、把下拉放搜索后面） <!-- @rule id=toolbar-order level=MUST cat=设计模式 detect=ast dtitle=工具栏元素顺序应各页一致：标题→tab→下拉→搜索→次按钮→主按钮 title=工具栏顺序固定为 标题→组件级tab→下拉→搜索→次按钮→主按钮 -->——顺序必须是 `标题→组件级tab→下拉→搜索→次按钮→主按钮`。
- ❌ **把组件级 tab 当标题放左侧** / **把页面级 tab 当功能组件放右侧**——tab 归属看层级：页面级/模块级=标题（左），组件级=功能（右）。
- ❌ **间距 / 内边距写裸值**（`gap: 12px`、`padding: 16px 24px`）——一律走令牌 `spacing-3 / spacing-4 / spacing-6`。
- ❌ **在元素上写 margin 拼间距**——间距由左右两组容器的 `gap` 提供。
- ❌ **一排放多个主按钮**——主操作唯一，其余降为次按钮。
- ❌ **把业务字段全平铺当过滤器**（十来个条件糊满两三行）——按「5.①」收折：高频前置、低频进「更多筛选」。
- ❌ **并列同义的条件各占一个框**（`ID` / `关键词` / `订单号` 三个搜索框并排）——它们之间不产生交集，应合并成一个多字段模糊搜索。
- ❌ **把有交集的维度做成 tab**（`我创建的 / 我关注的 / 我处理过的`）——一条记录可能同时属于多个，见 Tabs 段前置硬规则。

## 五、可照抄骨架

> ⛔ **工具栏样式的唯一数据源在 `el-theme/patterns/toolbar.scss`（全局层）。**
> 使用方**只写约定 class**——布局 / 元素间距 / 标题字阶 / 工具栏内 tab 对齐，全部已在源头处理好。 <!-- @rule id=toolbar-convention-class level=MUST cat=设计模式 detect=manual dtitle=工具栏标题、筛选、按钮的间距与对齐应各页一致 title=工具栏一律用源头约定 class .toolbar/__left/__right/__title，禁在使用方复刻 -->
> 在使用方 scoped 里重写这几条 = 局部私货（源头改了它不动），一律禁止。
> **需要页面自己写的只有留白**（见「三、留白」）：左右归页面内容区容器统一给，上下按标题层级取档（页面级 16 / 模块级下方 12）。

```vue
<template>
  <!-- 分支①：有标题 —— 标题左，其余全右 -->
  <div class="toolbar">
    <div class="toolbar__left">
      <h3 class="toolbar__title">页面标题</h3>
    </div>
    <div class="toolbar__right">
      <!-- 顺序：组件级 tab → 下拉 → 搜索 → 次按钮 → 主按钮 -->
      <el-tabs class="tabs-sub" v-model="view"><!-- 组件级 tab --></el-tabs>
      <el-select v-model="type" /><!-- 下拉选择器 -->
      <!-- 搜索框（见 search-pattern） -->
      <el-button>导出</el-button><!-- 次按钮 -->
      <el-button type="primary">新建</el-button><!-- 主按钮 -->
    </div>
  </div>

  <!-- 分支②：无标题、有筛选类 —— 筛选类左，操作按钮右 -->
  <!-- <div class="toolbar">
    <div class="toolbar__left"> 组件级 tab / 下拉 / 搜索 </div>
    <div class="toolbar__right"> 次按钮 / 主按钮 </div>
  </div> -->

  <!-- 分支③：无标题、无筛选类 —— 只有操作按钮，靠左 -->
  <!-- <div class="toolbar">
    <div class="toolbar__left"> 次按钮 / 主按钮 </div>
  </div> -->
</template>

<style scoped>
/* 左右由页面内容区容器统一给（spacing-6），工具栏只写上下 */
.toolbar { padding-block: var(--iflyv-spacing-4); }
</style>
```

### 标题两档

| 层级 | 标题标签（字阶，源头） | 页面自写的下边距 |
|---|---|---|
| **页面级**（页面标题 / 页面级 tab 栏） | `<h3 class="toolbar__title">` → `title-page` 26/48 | `spacing-4`（16） |
| **模块级**（模块标题 / 模块级 tab 栏） | `<h4 class="toolbar__title toolbar__title--module">` → `title-module` 18/36 | `spacing-3`（12） |

```vue
<!-- 模块级：标题加 --module 降字阶即可，无需额外类 -->
<div class="toolbar">
  <div class="toolbar__left">
    <h4 class="toolbar__title toolbar__title--module">我的项目</h4>
  </div>
  <div class="toolbar__right">…</div>
</div>
```

> 照抄要点：**只写 class，不写 CSS**；元素相对顺序恒为「标题→组件级tab→下拉→搜索→次按钮→主按钮」；左右归哪边按「三分支」判定；标题按层级选字阶档。每个元素本身仍套各自的组件/模式规范。
