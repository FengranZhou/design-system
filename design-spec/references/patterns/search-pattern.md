# 搜索框选型模式 (Search Pattern)

> 设计模式层规则。接到「加搜索框 / 搜索入口 / 列表筛选检索」任务时，**动手前必读本文件**，先按「选型判据」定形态、再按「强制做法」落地、避开「反例」、直接套用「可照抄骨架」。读之前不要凭直觉自拟搜索框样式或触发方式。
>
> 搜索框是**业务组件 `SearchMini`**（源头 `design-spec/components/SearchMini/`），不是手拼的 el-input。两种形态（常驻展开 / 收起态）由一个 `collapsed` prop 切换——**选哪种不是审美问题，而是由「搜索在当前页面是不是核心功能」决定**。

---

## 一、何时用（触发条件）

命中以下任一，即用本模式：

- 页面里要放一个**搜索 / 检索 / 关键词查询**入口。
- 列表页、表格页顶部要加**按关键词筛选**的能力。
- 任何"输入关键词 → 得到匹配结果"的场景。

> 反过来：**只要是"搜索"，就用 `SearchMini` 组件，不要自己用 `el-input` + 放大镜图标手拼。** 手拼会脱离组件、各处样式与触发逻辑不一致、源头更新不同步（见反例）。

---

## 二、选型判据（最关键的一步：先定形态）

搜索框有两种形态，**由「搜索在当前场景是不是核心功能」决定，不要凭感觉或为了美观选**：

| 判据 | 用哪种形态 | prop | 为什么 |
|---|---|---|---|
| 搜索在本页**是核心功能**（用户主要就靠它找东西，如搜索页、通讯录、知识库） | **常驻展开**（基础形式） | `collapsed=false`（默认） | 让用户一眼可见、直接可用，不必多点一下 |
| 搜索在本页**非核心功能**（辅助性、偶尔用，如详情页角落、工具栏里的一个次要筛选） | **收起态** | `collapsed=true` | 平时收成一个「🔍 搜索」按钮，省空间、不喧宾夺主，点击才展开 |

> **判断入口**：动手前先问自己一句——"这个页面，用户是主要靠搜索来完成任务，还是搜索只是个辅助入口？" 核心 → 展开；辅助 → 收起。

## 三、强制做法

### 1. 一律用 `SearchMini` 组件，不手拼 <!-- @rule id=search-use-searchmini level=MUST cat=设计模式 detect=regex dtitle=搜索框应是统一的标准样式与宽度，各页一致 title=搜索框一律用业务组件 SearchMini，禁 el-input+放大镜手拼 -->

```ts
import { SearchMini } from '<path>/design-spec/components'
```

- 展开态、收起态、放大镜位置、清除、防抖、动画都已在组件内处理好，接入方只传 prop。
- **绝不**用 `el-input` + 自己塞放大镜图标去复刻搜索框——那会脱离组件、不同步（见反例）。

### 2. 按选型判据传 `collapsed`

- 核心功能场景：`<SearchMini v-model="kw" @search="onSearch" />`（默认 `collapsed=false`，常驻展开）。
- 非核心场景：`<SearchMini collapsed v-model="kw" @search="onSearch" />`（收起态）。

### 3. 检索触发方式：默认实时，受限则点击 / 回车

- **默认实时搜索**：输入即触发（组件内置防抖，默认 300ms），`@search` 回调里发起检索。
- **若因技术限制不能实时**（如后端查询开销大、不宜每次输入都请求）：改为**点击右侧放大镜 / 按 Enter** 触发——组件已内置，点放大镜或回车都会 emit `search`。此时可把 `search-delay` 设为较大值或让业务侧只在 `@search` 里响应点击/回车。

### 4. 宽度与基础输入框一致

- 组件默认宽度与基础输入框一致（240px）。需要特殊宽度时，用 `style="--search-mini-width: 320px"` 一处覆盖，不散落改。

### 5. 搜索回调

- 统一走 `@search`（value: string）。实时输入防抖后、点击放大镜、按回车、清空，都会触发 `@search`。
- 不要另接 `@input` 去自己实现搜索——`@search` 已收敛了所有触发时机。

---

## 四、反例（禁止）

- ❌ **用 `el-input` + 自己塞放大镜图标手拼搜索框** —— 脱离 `SearchMini` 组件，样式/触发/收起逻辑各处不一致，源头更新不同步。
- ❌ **凭美观选形态**（"这里放个收起的好看"）—— 形态必须按「核心 / 非核心」判据定，不是审美选择。
- ❌ **在使用方 scoped 里覆盖搜索框外观**（`:deep(.el-input__inner)` 改字号/边框/圆角等）—— 搜索框外观归组件源头 + `el-theme` 源头，手写即私货、不同步。
- ❌ **把放大镜当纯装饰、另做一个"搜索按钮"** —— 组件的右侧放大镜本身就是可点击触发点，不必再加按钮。
- ❌ **实时场景仍强制用户点按钮才搜** —— 能实时就实时；只有技术受限才退化为点击 / 回车触发。

## 五、可照抄骨架

```vue
<template>
  <!-- 核心功能场景：常驻展开 -->
  <SearchMini v-model="keyword" @search="onSearch" placeholder="搜索" />

  <!-- 非核心场景：收起态（平时是「🔍 搜索」按钮，点击展开） -->
  <SearchMini collapsed v-model="keyword" @search="onSearch" placeholder="搜索" />
</template>

<script setup lang="ts">
import { ref } from 'vue'
import { SearchMini } from '<path>/design-spec/components'

const keyword = ref('')

// 实时/点击/回车/清空都会走这里；技术受限时业务侧只需保证在此发起检索即可
const onSearch = (value: string) => {
  // 发起检索：本地过滤 或 请求后端
}
</script>
```

> 照抄要点：**先按判据定 `collapsed`**（核心不传/false、非核心传 true），检索逻辑统一写在 `@search` 回调里；样式、收起展开、放大镜、防抖一概不用手写——全由 `SearchMini` 组件保证。
