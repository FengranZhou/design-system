# 展示型页面指南

> 适用于首页概览、数据报告、调研成果展示、对外汇报等"看"重于"操作"的页面。
> 效率型页面（管理后台、列表、表单）请查阅 `efficiency-guide.md`。

---

## 组件策略

| 层级 | 来源 | 职责 |
|------|------|------|
| 排版原子 | 自定义组件 | Hero 区、大号数据卡、引述块、多栏分栏、章节标题组、分割装饰等页面视觉主体 |
| 数据展示 | ECharts + 自定义容器 | 图表卡片、数据指标组、趋势面板 |
| 功能控件 | Element Plus | 筛选器、按钮、弹窗、下拉菜单——仅在用户需要操作时出现 |

- **EP 组件不承担视觉主体角色**，页面的视觉节奏由自定义排版组件主导
- **EP 组件外观一律不覆盖**（含展示型页面） <!-- @rule id=display-no-ep-override level=MUST cat=单一数据源 view=impl detect=regex title=展示型页面同样不得覆盖 EP 组件外观（需要不同观感就改源头或另做自定义排版组件） -->：需要不同观感时，改源头 `el-theme/components/*.scss` 或另做自定义排版组件承担视觉主体，**不在使用方 scoped / `:deep()` 里改 EP 组件的圆角、内边距等外观**——这是最高铁律的「局部私货」判定项，展示型页面不例外。

## 与效率型的关键差异

| 维度   | 效率型            | 展示型                                           |
| ---- | -------------- | --------------------------------------------- |
| 视觉重量 | 轻盈、克制          | 允许适度厚重感，为信息服务的装饰可以存在                          |
| 字号对比 | 相邻层级配对，≥1.25×  | 刻意跨级拉大至 2×~3×，用大号展示字体制造张力                     |
| 留白   | 呼吸感，但紧凑务实      | 大段留白作为节奏工具，段落间距可拉大至 `spacing-8`~`spacing-10`（32~40px，当前最大档） |
| 分隔手段 | 间距 > 色差 > 细线   | 可使用竖分割线分栏、`bg-inset` 大色块、pull quote 引述块等编辑式手法 |
| 投影   | 禁止卡片投影，阴影仅用于浮层 | 自定义排版组件允许微投影（见装饰手法）                           |
| 装饰   | 禁止纯装饰元素        | 允许服务于信息层级的装饰（色块背景、大号引述标记、数据可视化点缀）             |

## 展示型子风格

展示型页面按**叙事方式**分为三种子风格。动手设计前先确定子风格——它决定后续所有章节（构图、排版、装饰、动效）中各项能力的使用倾向和上限。

### 审美不变量

以下原则优先级高于任何子风格的具体允许项。当子风格描述与不变量冲突时，**以不变量为准**。

1. **协调优先于丰富**：配色的首要目标是整页协调舒适，而非色相数量多。品牌色 + 中性色是安全基线；展示型页面可根据前置确认的色彩基调另选主色调，辅助色按需引入——判断标准是信息维度是否需要区分，不是子风格等级
2. **中性色主导**：任何展示型页面的亮色区域，中性色（灰阶 + 白色）的视觉面积 ≥ 70%。子风格扩展的是「剩余 30% 怎么用」，不是「能不能突破 70/30」
3. **着色精度**：色彩进入页面的方式是精确的小面积锚点（指示条、边框、数字色、图表色阶），而非大面积填充（整个卡片背景涂实色、整个 Section 底色涂辅助色）。**例外清单**：Hero 区域背景、`step-1` 级浅底分区（面积大但浓度极低，视觉上仍属于中性范畴）
4. **通透底线**：遮住所有着色元素后，页面的信息结构和层级仍然清晰可读——色彩是加分项，不是依赖项
5. **五秒测试**：眯眼模糊化看整页亮色区域，如果彩色面积感 > 灰白面积感，说明用力过度，需要减色

### 如何选择

只问一个问题：**这个页面要用什么方式讲故事？**

| 子风格 | 叙事方式 | 选择信号 |
|--------|---------|---------|
| 结构化阅读 | 信息结构驱动节奏 | 页面核心是数据、分析、对比、趋势——读者需要"看懂" |
| 编辑式叙事 | 编排手法驱动节奏 | 页面核心是结论、成果、故事线——读者需要"被说服" |
| 沉浸式体验 | 空间感与视觉冲击驱动节奏 | 页面核心是能力、愿景、品牌印象——读者需要"被打动" |

> 子风格不与内容题材绑定。一个"AI 能力展示"页可以是沉浸式体验（发布会式），也可以是结构化阅读（技术白皮书式）。选择依据是叙事目标，不是内容类别。

### 结构化阅读

- **情绪方向**：理性、可信、专业、有阅读节奏
- **张力性格**：像排版精良的学术期刊——标题层级分明，关键发现被显著提炼，图表前后有呼吸间隔。节奏来自内容结构本身，而非视觉特效
- **视觉重心**：数据和结论是绝对前景；一切装饰和容器都为数据的可读性服务
- **装饰上限**：允许使用装饰手法表中的低强度手法；光斑、扫光、沉浸式背景不适用于此风格
- **动效天花板**：增强层轻度——仅允许 ScrollTrigger 一次性触发（计数、渐显），禁止 scrub / pin / WebGL <!-- @rule-skip n/a 子风格能力描述表的一行，非独立可判定规则 -->

### 编辑式叙事

- **情绪方向**：温和、进取、有成就感、叙事感
- **张力性格**：像杂志专题报道——刻意制造疏密对比，密集段之后紧接大留白或引述，让读者在"吸收"和"感受"之间交替。节奏不均匀是设计意图
- **视觉重心**：故事线和关键结论是前景；数据为结论提供支撑，但不抢占叙事主线
- **装饰上限**：可使用装饰手法表中的大多数手法；光斑、bg-inset 等营造氛围的手法在此风格中自然
- **动效天花板**：增强层中度——允许 stagger 序列、滚动渐显；pin 和 WebGL 非首选但不禁止 <!-- @rule-skip n/a 同上，且本行为「不禁止」语气，无强制力 -->

### 沉浸式体验

- **情绪方向**：沉浸、自信、有感染力
- **张力性格**：每一屏只讲一件事，用极端的尺度对比和空间感制造沉浸体验。留白不是呼吸，是舞台——可以是发布会式的科技冲击，也可以是画册式的人文沉浸等
- **视觉重心**：体验本身是前景；视觉效果不是装饰，而是信息传达的一部分
- **装饰上限**：装饰手法表全量可用；是唯一适合沉浸式背景和高强度 GSAP 编排的风格
- **动效天花板**：增强层完整——ScrollTrigger 全模式（once / scrub / pin）、WebGL、复杂 Timeline 均可用

## 构图原则

1. **一屏一焦点**：每个视口高度内只设一个视觉锚点（大号数字、核心图表、主标题），其余元素降级为陪衬
2. **阅读节奏感**：内容区按"重 → 轻 → 重"或"密 → 疏 → 密"交替排布，避免连续多个同等重量的区块
3. **纵向叙事线**：页面从上到下应有清晰的信息递进关系（总览 → 分项 → 细节），而非平铺并列

---

## 排版节奏

展示型页面通过**夸张的字号落差**制造视觉张力，层级之间刻意跨级拉大，而非相邻递进：

| 层级对比 | 最小字号比 | 示例 | 说明 |
|---------|-----------|------|------|
| Hero 主标题 vs 正文 | ≥ 3× | 48px vs 14px（3.4×） | 首屏核心信息必须一眼抓住视线 |
| 数据大字 vs 说明文字 | ≥ 3× | 56px vs 14px（4×） | KPI / 统计指标用大号展示字号拉开层次 |
| Section 标题 vs 正文 | ≥ 2× | 32px vs 14px（2.3×） | 章节切换时重建视觉锚点 |

- 同一区块内最多出现 **3 级**字号（标题 / 辅助文字 / 正文），超过则层级混乱
- 相邻两级字号比不低于 1.5×，低于此值视觉上无法形成清晰区分
- **行宽约束**：正文段落 `max-width: 80ch`（≈ 40 汉字），标题 `max-width: 36ch`（≈ 18 汉字），防止长行阅读疲劳。标题比正文窄一档，保持视觉收敛

## 组合规则

- **最大分栏数 ≤ 3**：展示型内容需要呼吸感，超过 3 栏会回到效率型的密度
- **大号元素不扎堆**：同一视口内不超过 2 个大号展示级元素（Display 标题、大号数字等）
- **图文比例**：数据可视化或插图面积占所在区块 40%~60%，不喧宾夺主也不沦为点缀
- **CTA 弱化**：展示型页面的操作按钮应退居次要位置（页面底部或角落），不打断阅读流
- **锚点/章节导航 ≤ 6 项**：展示型页面若有页内锚点导航或章节导航，条目不超过 6 个，超出需合并归类

## 配色策略（展示型增补）

在通用配色原则（见 `foundations.md > 配色原则`）基础上，展示型页面额外允许：

- **辅助色存在感更强**：效率型中辅助色多停留在 step-1~2 底色，展示型可提升至 step-3~5 用于图形和装饰，面积占比可接近主色
- **浅底色分区**：利用主色或辅助色的 step-1 作为整个 Section 背景底色，与 `bg-panel` 白色区块交替形成"彩 → 白 → 彩"节奏，单页不超过 3 处
- **数据可视化配色**：固定蓝打头（`blue-5`，不随品牌切换）+ 扩展色板跨色相取色，保持等视觉权重（同「数据可视化 > 配色」，已固化在 `Chart` 源头）；图表背景保持透明或 `bg-panel`

## 装饰手法

以下为常用手法参考，不限于此表。使用任何装饰手法均须服务于信息传达：

| 手法                | 用法                            | 限制                                                                                                                            |
| ----------------- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `bg-inset` 大色块    | 为核心数据区或引述区创建视觉锚点              | 单页不超过 2 处                                                                                                                     |
| 竖分割线              | 多栏 editorial 布局的栏间分隔          | 仅用于 2~3 栏之间，1px `border-default`                                                                                              |
| Pull quote 引述块    | 突出关键结论或引用语                    | 字号使用 `--iflyv-font-title-page` 或 `--iflyv-font-title-module`，不超过 2 行                                                          |
| Google Fonts 外部字体 | 标题、Slogan、大号数字等需要个性化调性的文本     | 选用与页面风格协调的字体；`@import` 或 `<link>` 引入时必须加 `&display=block`（加载期短暂隐藏文字，避免后备字体→目标字体的闪烁跳动）；仅用于展示型排版组件，EP 组件和正文不引入外部字体              |
| 大号展示数字            | 统计指标、KPI 展示                   | 搭配小号辅助说明文字；字体自由选择（Google Fonts 或系统内数字字体均可），字号 ≥ 28px，与说明文字保持 ≥ 3× 对比                                                          |
| 文字渐变填充            | 标题、Slogan 等短文本的色彩强调           | `background-clip: text` + 静态渐变；比文字扫光更轻量，适合不需要动效的场景；同一视口最多 2 处                                                                 |
| 文字扫光              | 标题关键词动态高亮                     | 同一视口最多 1 处，仅标题级文字（见「渐变光斑技法」）                                                                                                  |
| 几何纹理              | 背景质感增强（网格点阵、细线图案、等距圆点等）       | CSS 或 SVG `pattern` 实现；透明度极低（仅隐约可感知），不与前景内容争夺注意力；可与背景光斑叠加                                                                     |
| 背景光斑              | 在纯色底上叠加离散光晕，营造氛围层次            | SVG 椭圆 + 高斯模糊，绝对定位；同一容器最多 3 个，`pointer-events: none`（见「渐变光斑技法」）                                                               |
| 微投影               | 自定义排版组件的浮起感                   | 小偏移 + 大模糊 + 低透明度（如 `0 4px 24px rgba(30,60,120,0.08)`）；禁止纯黑投影；同一视口内带投影元素不超过 2 个；EP 组件不加投影；暗色模式下降低透明度或替换为微弱发光描边                 |
| 毛玻璃               | 叠在光斑或图片背景上的信息卡片               | `backdrop-filter: blur` + 半透明底色 + 双光源渐变描边（参考 `.surface-bordered` 的 135deg 渐变逻辑）；前提是背景有视觉内容（光斑/图片），纯白底上无效果；需确保前景文字对比度达标        |
| 旋转渐变描边            | 首屏核心交互入口（搜索框、CTA 按钮）的聚焦态或常驻动效 | `conic-gradient` 旋转动画 + `border-radius` 裁切；同一视口最多 1 个元素使用；动画速度宜慢（≥ 3s 一圈），避免分散注意力；`prefers-reduced-motion: reduce` 时降级为静态渐变描边 |
| 滚动驱动动效            | Section 入场、数字计数、路径绘制等         | 详见「滚动驱动动效」章节                                                                                                                  |
| 沉浸式背景             | Hero 区域 WebGL 流动渐变 + 鼠标交互     | 详见「沉浸式背景」章节                                                                                                                   |
| 开源图片              | Hero 背景、特征配图、编辑式叙事插图          | 来源限 Unsplash；须压缩至合理体积；不用于功能性 UI 元素（图标、按钮、头像占位）                                                                                |

## 视觉差异化

展示型页面应主动避免所有页面套用同一模板。设计时至少在以下维度中**选择 1 项**做出区分：

- 配色权重（主色/辅助色面积比例调整）
- 布局结构（单栏叙事 / 双栏对比 / 非对称分栏）
- 装饰手法（渐变背景 / 大号数字 / 引述块 / 光斑，选不同组合）

> 效率型页面不适用此规则——后台页面追求一致性，用户在不同管理页面间切换时需要熟悉感。

## 展示型反模式

- ❌ 信息平铺：所有区块等大等重，无焦点无节奏
- ❌ 装饰过载：色块 + 渐变 + 大字 + 插图同时出现在一个视口内
- ❌ 效率型伪装：展示型页面用表格/表单堆砌，缺少编辑式排版
- ❌ 空洞留白：大面积空白无信息支撑，留白不是"没东西放"而是"让重要的更突出"
- ❌ 模板坍缩：多个展示型页面视觉高度雷同，缺乏各自的内容特征表达

---

## 混合型页面

当同一页面包含展示型（概览/归纳）与效率型（全量操作）内容时，按以下原则处理：

1. **单向过渡**：展示型在上、效率型在下，只发生一次过渡，不反复交替
2. **视觉统一**：整页共享同一套配色、字体族和品牌调性，不因区块类型切换色系
3. **渐进收敛**：从上到下，信息密度逐步提高、装饰逐步退场、间距逐步收紧，是连续渐变而非硬切
4. **自然衔接**：展示区与效率区之间无需强分隔，用间距递减 + 字号回落自然过渡

## 数据可视化

### 配色

- **序列配色**：固定蓝色打头（`blue-5`，**不随品牌切换**——图表配色全站恒定），其余按序取扩展色板 green → orange → cyan → geekblue → red，**统一取第 5 级**（比语义强调档柔和一档），色相间保持等视觉权重，最多 6 色。**单序列一色**（首位蓝）——颜色编码"序列"而非"类目"，同一指标逐类目换色不携带信息且与图例矛盾——已固化在业务组件 `Chart` 源头
- **功能色语义不变**：红=负面/下降、绿=正面/增长，不因图表美观而混用
- **整体基调**：通透、自然。避免高饱和纯色大面积填充，优先使用带透明度的柔和色彩
- **亮暗适配**：图表色值通过 CSS 变量引用色板，暗色模式下自动获得暗色变体，无需单独配色。暗色下透明度可适当降低 5%~10%，避免在深色背景上过亮
- 图表背景保持透明或 `bg-panel`，不加额外底色

### 图形风格

- **柱状图**：偏细柱、柱体四角 2px 微圆角、填充色带适度透明度，避免实心色块感；**堆积柱/条**：段与段之间留 2px 白缝、每段四角 1px 微圆角（源头固化），段界靠留白而非描边线
- **折线图**：细线 + 小折点，可搭配渐变面积填充增加体积感
- **饼/环图**：优先环形图（donut），扇区间留间隙（仅环形——饼状是实心圆，留隙会在圆心汇成裂缝）
- **面积图**：填充色由上到下渐隐，不使用纯色填充

### 排版

- 图表标题使用页面内同级标题变量，不单独定义图表专属字号
- 坐标轴标签使用 `text-3` 色阶（不与正文争夺视觉权重）；图例文字用 `text-1`（序列名是可点击的主信息，与数值同权重）
- 网格线使用 `--iflyv-border-subtle`（最轻档），虚线优先
- 坐标轴线仅保留底部和左侧，右侧和顶部隐藏

### 交互

- hover tooltip 跟随 EP tooltip 风格（el-theme 已覆盖）
- 图表区域占所在区块 40%~60%（展示型组合规则已约束）

### 图表选型：什么数据用什么图（先定这个再谈配色）

**判据是"你想让读者比较什么"**，不是数据长什么样：

| 想表达 | 用什么图 | 别用什么 |
|---|---|---|
| **类目之间比大小**（各科平均分、各班人数） | **柱状图**（类目 ≤8）/ **条形图**（类目多或名称长，横向排更放得下） | 别用折线——类目之间没有连续关系，连起来是误导 |
| **随时间的变化趋势**（成绩趋势、出勤走势） | **折线图**（建议多序列 ≤4 条）/ **面积图**（只有 1 条且想强调累积量） | 别用柱状——时间点多了会挤成栅栏 |
| **占比构成**（分数段分布、及格/不及格） | **环形图**（扇区 ≤5，超 5 类源头自动并「其他」）/ **条形图**（每类都重要不能合并时逐类比大小）/ **堆叠图**（要同时比多个对象的构成） | 别用饼图（本系统优先环形）；**扇区超过 5 个别硬塞**，读者分不清 |
| **单个完成度 / 达成率**（课程完成度、及格率） | **环形进度**（单个大数字 + 环）或**数字 + 文字**直接说 | ⏸ `el-progress` 当前停用（见勿用清单），需要条形进度先与设计负责人确认 |
| **一个核心数字**（总人数、总课时） | **不用图**——直接 `--iflyv-font-number-display` 大号数字 + 说明文字 | 别为了"有图表"给单个数字套个图 |

> **先问"读者要拿这个数做什么决定"**：比大小→柱/条；看走势→折线；看构成→环/堆叠；只是知道个数→别画图。**图表不是越多越好**，一屏内图表超过 3 个就该考虑是不是有些数据直接用数字更清楚。

### 各图型细则（数量上限与硬判据）

> 整理自用户知识库《Web 图表设计指南》（陶菁）。选型先过上表，选定后按本节核对该图型的硬判据；
> 数量上限是**可读性上限**，不是能不能画的技术上限。

| 图型 | 硬判据 | 数量上限 |
|---|---|---|
| **折线图** | 随时间/有序类别的走势 | 建议折线 **≤4 条**；**横轴点位多不必换图**——**点位 >12 开 `Chart` 的 `zoomable`，≤12 不开**（底部范围选择控件 + 滚轮缩放，柱状同理） |
| **柱状图** | **横坐标必须是时间、日期等有序类别**——无序类别一律用条形图 <!-- @rule id=chart-bar-ordered-category level=MUST cat=视觉呈现 detect=manual dtitle=柱状图横轴应是有先后顺序的类别，无序类别应横排成条形图 --> | 建议并排系列 **≤4 组**（每个点位并排的柱子数，非横轴点位数）；横向空间不足/标签挤压时转条形图 |
| **条形图** | 无序类别的比大小；很灵活，常与数据表格结合（嵌入单元格作数值的视觉长度暗示） | 嵌表格时：几组数据**同类**（数值可比）→ 取全表最大值定最长条、其余按比例缩放；**不同类**（如播放量 vs 点赞量）→ 每纵列取各自最大值、**各列独立缩放**——搞混会把不可比的数据画成可比的样子；可用灰底保持列表宽度统一 |
| **堆积柱/条形图** | 包含关系的数据：总量 + 总量内各子分类 | 可多序列；序列 **≥3 时中间序列的长度难以直接比较**，需精确比较各子类时只放 2 个序列 |
| **环形图** | 单组数据看占比；**分类从大到小、12 点方向顺时针排，「其他」恒排末位**（`Chart` 源头已自动处理，下游免记）；环心放总数或留空 | 扇区 **≤5**（本系统从严）；**超 5 类源头自动合并**：保留前 4 大类、其余并入「其他」；**每一类都重要不能合并 → 别用环形，改条形图逐类比大小**；多组数据一起比构成 → 改堆积图 |
| **百分比堆积柱/条**（`stacked` + `percent`） | 不关心总量、只关心比例关系 | **只分 2 组**——分组 ≥3 时两端长度不固定、中间颜色无法比较；单组看比例用环形图 |
| **柱线图**（`type="bar-line"`） | 不同性质数据的相关关系（两种数据不可比 → 两种形式 + 两套坐标轴） | **双轴两侧顶部都必须标单位**（`unit` 左 / `unit2` 右）；**柱放更重要的数据、对应左轴**；不能出现第三种性质的数据 |
| **瀑布图**（`type="waterfall"`） | 增量趋势 + 总量（`data.value` 为增量，可负；绿增红减已固化） | **不支持多组数据** |
| **双向柱/条**（`diverging`） | 正负向或有相对性的数据（收入/支出、转入/转出） | **恰 2 个序列**（第二序列自动反向）；横排加 `horizontal` |
| **散点图**（`type="scatter"`） | 变量之间的相互影响程度；多序列即多色散点 | **两轴都必须标单位**（`x-unit` / `unit`） |
| **雷达图**（`type="radar"`） | 特质、能力指标的多维度比较 | **维度 ≥3 个**（过多降可读性）；分类 **≤4 组**——**超 4 组别硬叠**（多边形互相覆盖读不出高低），按序分流：① 只留重点对比对象，其余合成一条「平均」基准；② 按组拆成多张雷达并排；③ 改分组条形图 / 表格逐维度比 |
| **词云 / 韦恩图 / 热度地图**（未纳入 `Chart`） | 整体印象→词云；集合相交（≤3 个）→韦恩；地理分布→热度地图 | 词云需第三方插件依赖、韦恩 ECharts 无实现、地图需地理数据与审图合规——**确需使用先与设计负责人确认**，勿绕过组件自拼 |

### 图表通用构成（浮层 / 图例 / 坐标轴 / 标记）

以下已固化进 `Chart` 源头的标注 ✅，页面无需配置；未固化的按规则执行：

- ✅ **浮层（tooltip）表格化**：首行类别/时间标识，下方逐行「色点 + 系列名（左对齐）+ 数值（右对齐）」，多系列全部列出；bar 悬浮当前列半透明高亮；**无论有无数据均始终展示浮层**
- ✅ **图例**：统一顶部（环形图为右侧带数值占比）；**只有一组数据也展示图例**（保持多图统一）——单序列给 `Chart` 传 `series-name` 即出。**图表标题一律传 `Chart` 的 `title`**（组件内标题行，组件标题字阶居左）——横排图例与标题**同行右侧、垂直居中**（源头固化）；**禁在图表上方自拼标题行**（对不齐图例）；图例放不下时源头自动收纳为「+N」（点开面板查看并开关其余序列），头行高度恒定 <!-- @rule id=chart-title-legend-inline level=SHOULD cat=视觉呈现 detect=manual dtitle=图表标题与图例不同行：标题自拼在图表上方，图例掉到下一行左右都对不齐 -->

### ECharts 手拼骨架（回退路径才需要；Chart 内部即按此实现）

**ECharts 画在 canvas 里，读不到 CSS 变量**——直接写 `color: 'var(--iflyv-brand-primary)'` **不生效**（图表会变透明或黑色）。必须在 JS 里把令牌值取出来再喂给 option：

```ts
/** 从 CSS 变量取实际色值喂给 ECharts（canvas 读不了 var()） */
const token = (name: string) =>
  getComputedStyle(document.documentElement).getPropertyValue(name).trim()

const option = {
  // 背景透明，让它跟随所在卡片的底色（见上方「配色」段）
  backgroundColor: 'transparent',
  // 序列配色同「数据可视化 > 配色」：固定蓝打头 + 扩展色板，统一第 5 级（与 Chart 源头同一列表）
  color: [token('--iflyv-blue-5'), token('--iflyv-green-5'), token('--iflyv-orange-5'), token('--iflyv-cyan-5'), token('--iflyv-geekblue-5'), token('--iflyv-red-5')],
  textStyle: { color: token('--iflyv-text-3') },      // 轴标签走三级（图例文字在 legend.textStyle 单独取 text-1）
  xAxis: {
    axisLine: { lineStyle: { color: token('--iflyv-border-default') } },
    splitLine: { show: false },                        // 顶部/右侧轴线隐藏
  },
  yAxis: {
    axisLine: { show: false },                         // 只留底部与左侧
    splitLine: {
      lineStyle: { color: token('--iflyv-border-subtle'), type: 'dashed' },
    },
  },
}
```

**三条落地纪律**：

1. **切主题 / 切品牌色后必须重取色并重绘**——`getComputedStyle` 拿到的是取值那一刻的快照，`data-theme` 或 `data-brand` 变了图表不会自己变。监听主题切换后调 `chart.setOption(buildOption())`。
2. **容器必须有明确高度**，且 `resize` 时调 `chart.resize()`——ECharts 不会自适应父容器。
3. **图表容器的底色走 `bg-panel`**（白面板），`backgroundColor: 'transparent'` 让图表透出来即可，**不要在 option 里自己配底色**。

> **ECharts 本身不在本设计系统的组件覆盖范围内**（它不是 EP 组件、源头无 scss 适配）——本段约束的是**怎么让它的观感与设计系统一致**，不是把它纳入组件库。

## 渐变光斑技法

> 编码实现：光斑用 CSS `radial-gradient` + `filter: blur()`，动效走 `--iflyv-duration-*` / `--iflyv-ease-*` 令牌。

统一基于 **SVG linearGradient + feGaussianBlur** 实现。两种技法共享色系与 SVG 基础设施。

### 技法概览

| 技法 | 原理 | 视觉效果 | 典型场景 |
|------|------|---------|---------|
| 文字扫光 | SVG 圆形光斑作为 `background-image`，`background-clip: text` 裁切至文字轮廓，`linear` 匀速横向动画 | 彩色光点匀速掠过文字，经过处文字短暂变色 | 页面标题关键词、Hero 主标题、品牌 Slogan |
| 背景光斑 | SVG 椭圆 + linearGradient + feGaussianBlur，绝对定位于容器内 | 柔和的多色弥散光晕，营造氛围感 | Hero 背景、效率型页头背景、卡片悬浮光效 |

### 配色规律

每组渐变由 **3 个色标**线性过渡，与扫光 SVG 和背景光斑共用。配色遵循以下规律：

- **色相协调**：3 色在色轮上跨度 ≤ 90°；起点色不限于页面主色调——可选主色邻近色相或对比色相，但最终效果须与页面整体配色和谐共存
- **饱和度统一**：同组内饱和度保持接近，避免鲜艳色与灰调色混搭
- **明度有节奏**：3 色之间存在明度梯度，避免 3 色明度完全一致导致糊成一片
- **暗色模式适配**：通过 `--blob-*` CSS 变量整体降饱和 15%~25%，无需逐色调整

### 文字扫光

#### 光斑形状与尺寸

- **形状**：1:1 正方形 SVG（circle + linearGradient + feGaussianBlur σ=10），高斯模糊自然羽化边缘
- **尺寸倍率**（相对于 font-size，通过 `background-size` em 单位自动跟随字号）：

  | 变体 | 倍率 | 48px 字号时光斑尺寸 | 适用场景 |
  |------|------|-------------------|---------|
  | 标准 narrow | 2× | 96px | 短标题、标签、副标题 |
  | **中等（默认）** | **3×** | **144px** | 页面主标题、Hero 标题 |
  | 宽 wide | 4× | 192px | 超长标题、展示型大字 |

#### 动画参数

- **timing-function**：`linear`（匀速，无加减速顿挫感）
- **keyframes**：`0%` → sweep-start，`80%` → sweep-end，`100%` → sweep-end（80% 扫完 + 20% 尾部停顿后自然循环）
- **速度档位**（由 JS 根据元素宽度动态计算 `--sweep-duration`，确保不同文本长度下速度一致）：

  | 档位 | 目标速度 | 适用场景 |
  |------|---------|---------|
  | 常规 `.sweep-normal` | 120 px/s | 长文本、需要沉稳感 |
  | **默认** | **160 px/s** | 常规标题 |
  | 快速 `.sweep-fast` | 200 px/s | 短文本、需要快速吸引注意力 |

#### 约束

- 同一视口内最多 **1 处**扫光文字，避免多处同时闪烁分散注意力
- 仅用于**标题级文字**（`title-page` / `title-module` / `title-component`）与**展示数字**（`number-display*`），禁止用于正文、标签、按钮文字
- 扫光文字所在行的其余文字保持静态普通色，形成"局部点睛"而非"整行闪烁"

### 背景光斑

#### 模糊档位

feGaussianBlur `stdDeviation` 单位为 SVG userSpace（viewBox 200×200），渲染尺寸越大视觉模糊越强。

| 档位 | stdDeviation | 视觉特征 | 适用场景 |
|------|-------------|---------|---------|
| 聚焦 | 16 / 32 | 边界可辨、色彩集中 | 按钮光晕、小标题装饰、卡片悬浮光效 |
| 氛围 | 40 / 60 | 柔和弥散、有明确色域 | 效率型页头背景、Section 背景 |
| 环境 | 60 / 80 | 近乎无边界、大面积笼罩 | Hero 全屏背景 |

#### 不透明度

| 主题 | 环境光斑 | 氛围光斑 | 聚焦/悬浮光斑 |
|------|---------|---------|-------------|
| 亮色 | 0.12~0.20 | 0.18~0.25 | 0.20~0.30 |
| 暗色 | 0.08~0.12 | 0.12~0.15 | 0.12~0.20 |

#### 约束

- **同一视口内原则上只出现 1 组渐变光斑**（含文字扫光与背景光斑），避免多处光效同时争夺视觉焦点
- 同一容器内光斑不超过 **3 个**，建议使用 2~3 种不同色系增加层次
- 光斑必须 `pointer-events: none`，不影响交互
- 容器必须 `overflow: hidden`，光斑可溢出定位但不影响布局
- **禁止用于**：表单、表格、弹窗、抽屉等效率型组件内部 <!-- @rule id=lightspot-not-in-components level=MUST cat=视觉呈现 detect=manual dtitle=表单/表格/弹窗内部不应出现光斑等装饰效果 title=渐变光斑禁止用于效率型组件内部 -->
- **允许用于**：页面头部模块、Hero 区域、展示型 Section 背景、卡片悬浮光效（hover 触发）
- 光斑效果可通过 GSAP ScrollTrigger 改为滚动驱动或与鼠标交互联动（GSAP 按需动态加载，仅展示型页面可用）

## 滚动驱动动效

展示型页面的动效增强层，基于 GSAP ScrollTrigger + Timeline 实现滚动与动画的绑定。

### 适用场景

- **Section 滚动渐显**：内容区块滚入视口时渐现 + 微位移入场
- **KPI 数字计数**：统计指标进入视口时从 0 跑数到目标值
- **图表延迟入场**：ECharts 图表滚到才触发入场动画，避免首屏加载全部动效
- **多元素协同序列**：同一 Section 内多个子元素按 stagger 间隔依次入场

### 使用约束

- 同一视口内最多 **1 组**滚动动画序列，避免多组动画同时争夺注意力
- ScrollTrigger 模式选择：
  - **一次性入场**：`once: true` 触发后不再逆向，适用于大多数内容渐显
  - **进度联动**：`scrub` 模式将动画进度与滚动位置绑定，适用于视差效果
  - **固定叙事**：`pin` 模式固定元素在视口内，适用于分步叙事或数据故事
- 效率型页面及 EP 组件内部**禁止使用**
- `prefers-reduced-motion: reduce` 时跳过动画，直接显示最终态

### 与 CSS 基础层的关系

ScrollTrigger 编排的子动画可复用 `--iflyv-duration-*` / `--iflyv-ease-*` 变量值，保持全局节奏一致。增强层不替代基础层——hover、focus 等微交互仍由 CSS transition 处理。

> GSAP 按需动态 import，不进主包；仅展示型页面可用（效率型禁止引入，见 foundations「动效技术分层」）。

## 沉浸式背景

### 设计意图

展示型页面的背景不是静态画布，而是一个有感知力的环境——**"aware, not reactive"**。用户的存在应被环境感知到，但环境永远是背景，不反客为主。

### 动态背景

允许在 Hero / 展示型 Section 使用 WebGL / Canvas 实现流动渐变、粒子场等动态背景效果。动态背景为页面注入生命力，使展示型页面区别于效率型的静态界面。

### 鼠标交互反馈

用户的存在应被环境感知到。交互反馈的形式和强度不做限定，但它始终是背景的一部分，不能反客为主抢占前景内容的注意力。

### 质量底线（硬规则）

- 所有跟随效果必须使用**时间插值（lerp）**，禁止瞬时跟随
- 鼠标离开或触屏设备上，效果必须**自然衰减**到默认状态
- 保持 **60fps**，必须提供 CSS / SVG 静态降级方案
- 交互反馈的视觉强度**永远低于**前景文字和控件
- `prefers-reduced-motion: reduce` 时关闭动态效果，保留静态底图

### 不限定的部分

着色器算法、视觉风格、交互半径与强度、色彩变化方式、技术方案选型——这些留给具体实现时根据页面调性决定。

### 适用范围

仅 Hero 区域和展示型 Section 背景。效率型页面及 EP 组件内部**禁止使用**。

> WebGL 背景按需动态 import，需提供降级方案（不支持 WebGL 时回退静态渐变底）。

## 响应式策略

> ⛔ 与效率型同一前提：**1200px 是硬下限**（`--iflyv-layout-min-width`），窄于此出横向滚动、不继续压缩。**不存在 1200 以下的断点**，响应式只发生在 ≥1200 区间。详见 `efficiency-guide.md`「响应式策略」与 `foundations.md`「页面最小宽度」。

| 断点 | 展示型策略 |
|------|----------|
| ≥1440 | 正常布局（设计基准） |
| 1200~1439 | 正常布局；多栏区块可降一栏（如 3 栏→2 栏），图表宽度自适应容器 |
| <1200 | **不设断点**——整页出横向滚动条，维持 1200 形态 |

- 图表用容器百分比宽度 + `resize` 重绘，**不要**按视口断点写死尺寸。
- **不写 `<1200` 的断点**（含 `100vw` 类随视口收缩的值）——横向滚动语境下会算出错误值。
